## 一、架构设计

### 1.1 整体架构

本项目采用**模块化分层设计**，按职责将功能拆分为 4 个独立模块，各模块可独立运行，也可组合使用：

```
┌─────────────────────────────────────────────────────────┐
│                     数据来源 (Telegram 导出)               │
│                      result.json (JSON)                  │
└──────────────────────────┬──────────────────────────────┘
                           │
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
   ┌──────────────┐ ┌──────────────┐ ┌──────────────┐
   │ sql_converter│ │ importer_gui │ │ heatmap_viz  │
   │  (CLI 转换)   │ │  (GUI 导入)  │ │ (数据处理)   │
   └──────┬───────┘ └──────┬───────┘ └──────┬───────┘
          │                │                 │
          ▼                ▼                 ▼
   ┌──────────────┐ ┌──────────────┐ ┌──────────────┐
   │  SQLite DB  │ │  SQLite DB  │ │processed.json│
   └──────┬───────┘ └──────┬───────┘ └──────┬───────┘
          │                │                 │
          └────────────────┘                 ▼
                                   ┌──────────────┐
                                   │  ECharts 页面│
                                   │ (热力图可视化)│
                                   └──────────────┘

   ┌──────────────┐
   │ chat_viewer  │  ← 纯前端，直接读取 JSON 渲染
   │ (聊天查看器)  │
   └──────────────┘
```

### 1.2 数据流

1. **输入**：Telegram 桌面端导出的 JSON 文件（含 `name`、`type`、`id`、`messages[]`）
2. **转换**：Python 解析 JSON，写入 SQLite（结构化 + 索引）
3. **分析**：数据处理脚本读取 JSON/DB，分词统计，生成中间 JSON
4. **可视化**：前端页面加载中间 JSON，通过 ECharts 渲染图表

### 1.3 设计原则

| 原则 | 实践 |
|------|------|
| 单一职责 | 每个模块/类只负责一类功能（DB 管理 / 导入逻辑 / UI） |
| 零外部依赖 | GUI 核心仅用标准库，降低部署门槛 |
| 数据安全 | 原始数据只读，转换产物独立存储，不修改源文件 |
| 幂等性 | 重复导入不会产生脏数据（INSERT OR IGNORE + ID 去重） |
| 可扩展 | `raw_json` 字段保留完整原始数据，便于后续扩展 |

## 二、模块说明

### 2.1 importer_gui — GUI 导入工具（主程序）

**入口**：`main.py` → `TkinterApp.main()`

| 文件 | 职责 | 关键类/函数 |
|------|------|-------------|
| `main.py` | GUI 界面 + 主循环 | `TkinterApp` |
| `db_manager.py` | 数据库连接与所有 SQL 操作 | `DatabaseManager` |
| `importer.py` | JSON 解析、去重、批量导入 | `JSONImporter` |
| `test_import.py` | 集成测试 | `test_import()` |
| `sample_data.json` | 合成示例数据（无隐私） | — |

**界面架构**：
- 三标签页设计：`导入数据` / `数据统计` / `导入历史`
- 异步导入：后台 `threading.Thread` 执行，通过 `self.after(0, callback)` 回调 UI 线程
- 暗色主题：通过 `ttk.Style` 全局配置 Catppuccin Mocha 配色

### 2.2 sql_converter — 命令行转换工具

**入口**：`json_to_sqlite.py` → `main()`

精简版转换脚本，无 GUI 依赖。读取同目录 `result.json`，生成 `telegram_chat.db`。

| 文件 | 职责 |
|------|------|
| `json_to_sqlite.py` | 建库建表 + 批量插入消息 |
| `verify_db.py` | 数据库内容验证查询 |

### 2.3 heatmap_visualization — 热力图可视化

**入口**：`data_processor.py`（处理）→ `run.py`（服务）

| 文件 | 职责 |
|------|------|
| `data_processor.py` | 解析 JSON，构建活跃度热力图、话题热力图、每日趋势、用户排行 |
| `run.py` | 启动 `http.server` 本地静态服务，自动打开浏览器 |
| `index.html` | ECharts 热力图可视化页面 |

**分词策略**：优先使用 `jieba`（如已安装），否则回退到基于正则的简单字符分割。

### 2.4 chat_viewer — Telegram 风格聊天查看器

**纯前端**，无后端依赖。

| 文件 | 职责 |
|------|------|
| `index.html` | 页面结构 |
| `style.css` | 样式（含深色/亮色主题变量） |
| `app.js` | 数据加载、渲染、搜索、筛选、回复跳转逻辑 |

## 四、数据库表结构详解

### 4.1 chat_info — 群组信息

```sql
CREATE TABLE chat_info (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    chat_name  TEXT NOT NULL,   -- 群组名称
    chat_type  TEXT NOT NULL,   -- 群组类型 (private_supergroup 等)
    chat_id    TEXT NOT NULL    -- 群组原始 ID
);
```

### 4.2 messages — 消息主表

```sql
CREATE TABLE messages (
    id                   INTEGER PRIMARY KEY,  -- Telegram 消息 ID
    chat_id              TEXT NOT NULL,         -- 发送者/操作者 ID
    message_type         TEXT NOT NULL,        -- message / service
    date                 TEXT,                  -- ISO8601 日期
    date_unixtime        INTEGER,              -- Unix 时间戳
    sender_name          TEXT,                  -- 发送者昵称
    sender_id            TEXT,                  -- 发送者原始 ID
    text_content         TEXT,                  -- 纯文本内容
    reply_to_message_id  INTEGER,              -- 回复目标 ID
    forwarded_from       TEXT,                  -- 转发来源
    media_type           TEXT,                  -- 媒体类型 (sticker 等)
    raw_json             TEXT                   -- 完整原始 JSON
);
```

### 4.3 text_entities — 文本实体

```sql
CREATE TABLE text_entities (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    message_id   INTEGER NOT NULL,  -- 关联消息 ID (FK)
    entity_type  TEXT NOT NULL,     -- plain/emoji/bold/code/link/mention...
    entity_text  TEXT               -- 实体文本
);
```

### 4.4 import_log — 导入日志

```sql
CREATE TABLE import_log (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    import_time     TEXT,            -- 导入时间
    json_file       TEXT,            -- JSON 文件名
    total_messages  INTEGER,         -- JSON 中消息总数
    imported_count  INTEGER,         -- 实际导入数
    skipped_count   INTEGER,         -- 跳过（重复）数
    status          TEXT              -- success / failed
);
```

## 五、常用 SQL 查询示例

```sql
-- 1. 统计每个用户的发言频率
SELECT sender_name, COUNT(*) AS msg_count
FROM messages WHERE sender_name IS NOT NULL
GROUP BY sender_name ORDER BY msg_count DESC;

-- 2. 按日期统计消息量
SELECT substr(date, 1, 10) AS day, COUNT(*) AS count
FROM messages GROUP BY day ORDER BY day;

-- 3. 查找包含关键词的消息
SELECT id, sender_name, date, text_content
FROM messages WHERE text_content LIKE '%关键词%'
ORDER BY date_unixtime;

-- 4. 查询回复链
SELECT m1.id, m1.text_content, m2.text_content AS reply_text
FROM messages m1
LEFT JOIN messages m2 ON m1.reply_to_message_id = m2.id
WHERE m1.reply_to_message_id IS NOT NULL LIMIT 100;

-- 5. 查找转发消息
SELECT date, sender_name, text_content, forwarded_from
FROM messages WHERE forwarded_from IS NOT NULL
ORDER BY date_unixtime;

-- 6. 按时间段查询
SELECT * FROM messages
WHERE date_unixtime BETWEEN ? AND ?
ORDER BY date_unixtime;
```

## 六、开发规范

### 6.1 代码风格

- 遵循 **PEP 8** 规范
- 使用**类型注解**（Type Hints）
- 模块化设计，单一职责
- 中文注释说明业务逻辑，英文命名标识符

### 6.2 命名约定

| 类别 | 约定 | 示例 |
|------|------|------|
| 类 | PascalCase | `DatabaseManager` |
| 函数/方法 | snake_case | `insert_messages_batch` |
| 常量 | UPPER_CASE | `DARK_BG` |
| 私有成员 | 前缀 `_` | `_setup_styles` |

### 6.3 文件组织

```
模块目录/
├── 核心代码（入口 + 数据层 + 业务逻辑）
├── 测试（test_*.py）
├── 数据（输入 *.json 只读 / 输出 *.db 运行时生成）
└── 文档（README.md）
```

### 6.4 提交规范（约定式提交）

```
<type>(<scope>): <description>

type: feat | fix | docs | style | refactor | test | chore
```

示例：`feat(importer): 增量导入支持断点续传`

### 6.5 安全规范

- **禁止**提交真实聊天数据（`.json`、`.db`）至版本库
- **禁止**在源码中硬编码密钥、令牌、凭证
- 使用参数化 SQL 查询，防止注入
- 敏感配置通过环境变量注入

### 6.6 GUI 开发规范

- 所有耗时操作在后台线程执行，通过 `widget.after(0, callback)` 回调主线程
- UI 线程禁止阻塞
- 主题样式通过 `ttk.Style` 集中配置，不内联硬编码
- 使用 `protocol("WM_DELETE_WINDOW", handler)` 处理关闭事件，确保资源释放

## 七、EXE 打包指南

使用 PyInstaller 将 GUI 导入工具打包为独立 EXE：

```bash
cd importer_gui

pyinstaller --onefile --windowed --name "TG群聊SQL导入工具" ^
    --hidden-import db_manager --hidden-import importer ^
    main.py
```

参数说明：
- `--onefile`：打包为单个 EXE
- `--windowed`：无控制台窗口（GUI 应用）
- `--name`：输出文件名
- `--hidden-import`：显式声明隐式依赖模块

产物位于 `importer_gui/dist/` 目录。

## 八、扩展指南

### 添加新的统计维度

在 `db_manager.py` 的 `get_statistics()` 方法中添加 SQL 查询并写入返回字典。

### 自定义导入逻辑

继承 `JSONImporter` 并重写 `filter_new_messages()` 方法实现自定义去重策略。

### 添加导出功能

调用 `DatabaseManager` 的查询方法获取数据，导出为 CSV / Excel / JSON。

### 全文检索

基于 SQLite FTS5 扩展添加全文搜索能力：

```sql
CREATE VIRTUAL TABLE messages_fts USING fts5(
    text_content, sender_name,
    content=messages, content_rowid=id
);
```
