## 1. 文件组织规范

### 1.1 目录结构

- ✅ **所有新操作在子文件夹中完成**

## 3. 数据处理规范

### 3.1 数据兼容性

#### 消息文本格式
Telegram 导出的 `text` 字段有两种格式，必须兼容：

```python
def extract_text(msg):
    text = msg.get('text', '')
    if isinstance(text, list):
        # 数组格式：[{"type": "plain", "text": "Hello"}, ...]
        parts = [entity.get('text', '') for entity in text 
                if isinstance(entity, dict)]
        return ''.join(parts)
    return str(text) if text else ''
```

#### 发送者字段
```python
def get_sender(msg):
    # 普通消息用 from，服务消息用 actor
    return msg.get('from') or msg.get('actor') or '未知'
```

### 3.2 分词处理

#### 停用词管理
- 停用词表存储在 `STOP_WORDS` 集合中
- 添加停用词时需验证不影响统计结果
- 区分通用停用词和业务停用词

#### 分词策略
- 中文：双字组合 + 整词
- 英文：按空格分词
- 数字：4位以下有效
- 避免过度分词导致噪声

### 3.3 性能考虑
- 处理 2 万条消息应在 5 秒内完成
- 输出 JSON 文件控制在 5MB 以内
- 前端图表数据量合理（热力图最多 168 个单元格）

## 4. 安全规范

### 4.1 数据安全
- ❌ 不要将 `result.json` 提交到公共仓库
- ✅ 处理后的数据可公开（已脱敏）
- ✅ 原始数据本地保存即可

### 4.2 代码安全
- ✅ 使用 HTTPS CDN 加载 ECharts
- ❌ 不要在代码中硬编码敏感信息
- ✅ 启动服务时不暴露敏感路径

### 4.3 隐私保护
- ✅ 可视化数据中不展示用户 ID
- ✅ 消息内容仅展示关键词，不展示原文
- ❌ 不要添加导出原始消息的功能

## 7. 扩展注意事项

### 7.1 添加新图表
1. 在 `data_processor.py` 添加对应的数据处理函数
2. 在 `processed_data.json` 输出中添加新字段
3. 在 `index.html` 添加新的图表容器和初始化代码
4. 更新本文档

### 7.2 替换数据
1. 备份当前 `result.json`
2. 复制新的 JSON 文件到本目录
3. 运行 `data_processor.py` 重新处理
4. 刷新浏览器查看结果

### 7.3 升级依赖
- ECharts: 更新 CDN 链接版本号
- Python: 保持 3.8+ 兼容性
- 新增库：在文档中说明并更新 requirements

## 8. 常见陷阱

### 8.1 JSON 解析
- Telegram 导出的日期格式依赖系统 locale
- `date_unixtime` 是字符串类型，需要转换
- 消息 ID 可能不连续

### 8.2 浏览器兼容
- `fetch` API 需要现代浏览器
- ECharts 5.x 不支持 IE
- 暗色主题使用 `dark` theme 初始化

### 8.3 中文分词
- 简单分词可能产生噪声
- 停用词表需要持续优化
- 网络用语和表情难以处理
